# DESIGN.md — дизайн-система Studio CRM

Утверждённое направление: сразу рабочая CRM без лендинга; белый, почти чёрный и мягкий светло-серый как основа плюс **один сдержанный синий акцент** для интерактивных элементов; боковая навигация; Kanban для сделок; крупные диаграммы в серых скруглённых блоках; весь интерфейс на русском.

Mobbin здесь — **визуальный референс, а не образец для копирования**. Берём приёмы: плотную крупную типографику, контраст масштаба, капсулы «чёрная + серая», белое на сером, скругления. Не берём логотип, тексты, иконки чужих приложений, контент и маркетинговую структуру сайта.

**Ревизия шага 05 (визуальная доработка):** типографика стала плотнее и крупнее, добавлен синий акцент, одинаковые серые прямоугольники заменены тремя уровнями блоков (раздел 5), колонки воронки облегчены. Эти правила обязательны для шагов 06–14.

Значения сняты по пропорциям со скриншотов, а не из исходного CSS, и приведены к сетке этой системы. В конфликте между скриншотом и контрастом выигрывает контраст.

## 1. Принципы

1. **Сначала данные.** На экране главное — лиды, сделки, суммы, сроки. Украшений нет.
2. **Масштаб вместо цвета.** Иерархию создают размер, вес и серые оттенки. Заголовок страницы крупный и плотный, вторичный текст заметно светлее и мельче.
3. **Чёрный — это главное действие.** Чёрная капсула у основной кнопки области и у самых важных сигналов («Просрочено»). Одна чёрная кнопка на область.
4. **Синий — это «можно нажать».** Акцент используется только для интерактивного: ссылки, иконка активного пункта меню, кольцо фокуса, позже — одна ключевая кнопка процесса на экране. Данные, статусы и украшения синим не красятся.
5. **Три уровня блоков, а не одинаковые прямоугольники:** серая подложка с белыми плитками для KPI; крупный серый блок с белым полем для аналитики и пустых разделов; лёгкая секция без подложки с тонкой линией для списков и сводок.
6. **Цвет никогда не единственный сигнал.** Состояние всегда передаётся текстом и, где нужно, иконкой.

## 2. Что взято из референсов

| Скриншот | Что видно | Как применяем |
|---|---|---|
| 1. Hero, тёмный футер | Плотные заголовки, две пилюли «чёрная + серая», тёмная плавающая плашка cookie | Пара кнопок «основная + вторичная»; тёмная плашка становится тостом |
| 2. Сетка «One library» | Крупные серые скруглённые карточки, внутри белое содержимое | Аналитические блоки дашборда: серый блок, заголовок, белое поле с диаграммой |
| 3. «Clean dashboards» | Приглушённый серый текст, заголовок с иконкой, горизонтальная лента карточек | Kanban: горизонтальная прокрутка, заголовок колонки над полем, иконки у закрытых стадий |
| 4. Галерея | Серая рамка с белой панелью, пилюля поиска, вкладки с подчёркиванием, кнопка «Filter» | KPI — белые плитки на одной серой подложке; поиск, вкладки, фильтры (шаги 07, 09) |
| 5. Главный hero | Гигантский плотный заголовок, серый подзаголовок, пара капсул, синяя иконка как единственный цвет | Плотный крупный заголовок страницы, подзаголовок `lead` серым, пара капсул в шапке; один синий акцент |

**Намеренно отклоняемся:** верхнее меню заменено боковой навигацией; заголовки крупные, но не маркетинговые (40 px, а не 80); лендинга, блоков маркетинга и тёмного футера нет.

## 3. Токены

Токены объявляются в `:root` и подключаются к Tailwind. Значения вне токенов в компонентах не используются.

### 3.1. Цвет

```css
:root {
  /* Поверхности */
  --surface-page: #FFFFFF;      /* фон приложения */
  --surface-subtle: #F8F8F8;    /* поле колонки Kanban, наведение на пункт меню */
  --surface-block: #F4F4F4;     /* серые блоки и подложка KPI */
  --surface-card: #FFFFFF;      /* белое внутри серого */
  --surface-control: #EDEDED;   /* вторичная кнопка, поле поиска, активный пункт меню */
  --surface-control-hover: #E3E3E3;
  --surface-inverse: #141414;   /* основная кнопка, тост, бейдж «Просрочено» */
  --surface-inverse-hover: #2E2E2E;

  /* Текст */
  --text-primary: #141414;
  --text-secondary: #6B6B6B;    /* 5,33:1 на белом, 4,85:1 на #F4F4F4, 4,55:1 на #EDEDED */
  --text-disabled: #A3A3A3;     /* только для неактивных элементов */
  --text-inverse: #FFFFFF;

  /* Акцент — единственный цвет */
  --accent: #1F5BFF;            /* 5,26:1 на белом, 4,79:1 на #F4F4F4; белый текст на нём 5,26:1 */
  --accent-hover: #1749D6;      /* 7,1:1 на белом */

  /* Линии */
  --line-subtle: #EBEBEB;       /* разделители, граница сайдбара */
  --line-control: #8C8C8C;      /* граница полей: 3,36:1 на белом, 3,06:1 на сером */
  --line-focus: var(--accent);  /* кольцо фокуса с клавиатуры */

  /* Диаграммы */
  --chart-primary: #141414;
  --chart-secondary: #6B6B6B;
  --chart-tertiary: #A3A3A3;
  --chart-grid: #E3E3E3;
}
```

**Где синий допустим:**

| Можно | Нельзя |
|---|---|
| Текстовые ссылки и ссылки со стрелкой («Все лиды →») | Заголовки, подписи, данные, суммы |
| Иконка активного пункта меню | Фон блоков, карточек, колонок |
| Кольцо фокуса с клавиатуры | Бейджи статусов, стадии, KPI |
| Одна ключевая кнопка процесса на экране, например «Конвертировать» (вводится, когда появится) | Столбцы диаграмм и любое кодирование данных |
| — | Синий текст на `surface-control` (4,49:1 — ниже нормы) |

Других цветов нет: ни красного для ошибок, ни зелёного для успеха. Светлая тема единственная, тёмная в MVP не входит.

### 3.2. Типографика

Шрифт: **Inter** (variable) через `next/font/google`, подмножества `latin` и `cyrillic`, **ось `opsz`** (`font-optical-sizing: auto`): на крупных кеглях начертание становится плотнее, как Inter Display, мелкий текст остаётся читаемым. Запасной стек: `system-ui, -apple-system, "Segoe UI", Roboto, sans-serif`. Цифры в таблицах, KPI и суммах: `tabular-nums`.

| Токен | Размер / строка | Вес | Трекинг | Где |
|---|---|---|---|---|
| `title-1` | 32→40 (`clamp`) / 1.1 | 700 | −0.035em | Заголовок страницы |
| `display` | 32 / 36 | 650 | −0.03em | Значение KPI |
| `title-2` | 20 / 26 | 650 | −0.02em | Заголовок блока и секции |
| `title-3` | 16 / 22 | 600 | −0.01em | Название колонки, заголовок пустого состояния |
| `lead` | 17 / 24 | 400 | 0 | Подзаголовок страницы, всегда `text-secondary` |
| `body` | 15 / 22 | 400 | 0 | Основной текст, таблицы, поля |
| `small` | 13 / 18 | 400 | 0 | Подписи KPI, вторичные данные, бейджи, оси |
| `caption` | 12 / 16 | 500 | 0 | Подписи групп фильтров, шапка таблицы |

Веса: кнопки — 600 с трекингом −0.01em; активный пункт меню — 600, остальные — 500; ссылки — 500. Знак «Studio CRM»: 20 px, 700, −0.04em, слово «CRM» серым.

Кириллица шире латиницы: в длинных заголовках разрешён перенос; плотнее −0.035em не трекать. Заглавные буквы для оформления не применяются. Таблицы и формы остаются на `body` — крупная типографика только в заголовках и KPI.

### 3.3. Отступы, скругления, размеры

- **Шаг сетки 4 px:** 4, 8, 12, 16, 20, 24, 32, 40, 56.
- **Скругления:**

| Токен | Значение | Где |
|---|---|---|
| `radius-pill` | 999 px | Кнопки, поиск, чипы, бейджи, тост |
| `radius-xl` | 28 px | Серые блоки и подложка KPI |
| `radius-lg` | 20 px | Белые поля и плитки внутри блоков (28 − 8 px отступа), поле колонки Kanban, диалог |
| `radius-md` | 14 px | Карточка сделки |
| `radius-sm` | 10 px | Поля форм, строки меню выпадающего списка |

- **Высота элементов:** кнопка и поле 40 px; маленькая кнопка 32 px; строка таблицы от 52 px; минимальная цель касания на телефоне 44 px.
- **Тени:** только диалог, тост, выпадающее меню и перетаскиваемая карточка: `0 12px 32px rgb(0 0 0 / 0.14)`. У блоков и обычных карточек теней нет.
- **Анимация:** 150 мс `ease-out`, только `opacity`, `transform` и цвета. При `prefers-reduced-motion` отключается.
- **Фокус:** только `:focus-visible` — кольцо 2 px `--line-focus` со смещением 2 px при навигации с клавиатуры; после клика мышью кольца нет. `outline: none` без замены запрещён.

- **Сайдбар:** 248 px (216 px при 1024–1279), белый, граница справа `line-subtle`, фиксирован по высоте окна. Текстовый знак «Studio CRM» (раздел 3.2), без графического логотипа.
- **Порядок пунктов:** Дашборд, Лиды, Воронка, Сделки, Компании, Контакты.
- **Пункт меню:** 40 px (44 px на телефоне), `radius-pill`, иконка 18 px. Активный: фон `surface-control`, текст `text-primary` весом 600, **иконка синяя**, `aria-current="page"`. Неактивный: текст `text-secondary` весом 500, при наведении фон `surface-subtle` и чёрный текст. Чёрная заливка для навигации не используется.
- **Контент:** поля 16 px на телефоне, 32 px с 640 px, 48 px с 1280 px; максимальная ширина 1440 px.
- **Шапка страницы:** `h1` (`title-1`), под ним `lead` серым; справа пара капсул «чёрная + серая», если на странице есть действия. С 768 px капсулы стоят в одну строку и не сжимаются. Глобальный поиск появится на шаге 09.

**Адаптивность:**

| Ширина | Поведение |
|---|---|
| ≥ 1280 | Полный сайдбар, KPI 4 в ряд, аналитика 7 : 5 |
| 1024–1279 | Сайдбар 216 px, KPI 2 × 2, аналитика 2 равные колонки |
| 640–1023 | Верхняя панель с выезжающим меню, KPI 2 × 2, аналитика в 1 колонку |
| < 640 | Поля 16 px, KPI 2 × 2, таблицы превращаются в карточки-строки, Kanban прокручивается по колонкам с привязкой |

Прокрутка по горизонтали допустима только внутри Kanban.

## 5. Компоненты

### Кнопки

| Вариант | Вид | Применение |
|---|---|---|
Все кнопки — капсулы 40 px, текст 15 px весом 600, отступы 20 px; иконка-стрелка справа у навигационных действий («Лиды →»).

| Вариант | Вид | Применение | Статус |
|---|---|---|---|
| Основная | `surface-inverse`, белый текст | Одно главное действие области | Есть (`button.tsx`) |
| Вторичная | `surface-control`, чёрный текст | «Отмена», «Изменить», второе действие | Есть (`button.tsx`) |
| Акцентная | `--accent`, белый текст, наведение `--accent-hover` | Одна ключевая кнопка процесса на экране («Конвертировать») | Вводится на шаге 10 |
| Тихая | Прозрачная, при наведении `surface-control` | Действия в строках и меню | Вводится на шаге 06 |
| Опасная | Белая, граница 1,5 px `text-primary`, иконка корзины | Удаление. Всегда с подтверждением | Вводится на шаге 06 |

Акцентная и основная кнопки рядом не ставятся. Неактивная: `text-disabled`, причина рядом текстом. Загрузка: индикатор на месте иконки, ширина не меняется, повторное нажатие заблокировано.

### Ссылки

Текстовая ссылка — `--accent`, вес 500; при наведении `--accent-hover` и подчёркивание. Ссылка со стрелкой (`arrow-link.tsx`) — в правом углу заголовка блока или секции: «Все лиды →», «Воронка →».

### Поиск и фильтры

- **Поиск:** пилюля 40 px, фон `surface-control`, иконка лупы, плейсхолдер в цвете `text-secondary`.
- **Панель фильтров:** строка над таблицей: вкладки слева (подчёркивание 2 px активной), кнопка «Фильтры» и сброс справа.
- **Чипы:** пилюля 32 px. Выбран: чёрная заливка и белый текст. Не выбран: `surface-control`.
- **Группа фильтра:** подпись `caption` серым, значения чипами — приём со скриншота 4.
- Состояние фильтров хранится в URL.

### Поля форм

40 px, `radius-sm`, белый фон, граница 1 px `line-control`; фокус: кольцо 2 px `line-focus` со смещением 2 px. Подпись над полем `small`, всегда видима. Обязательное поле: «обязательно» текстом рядом с подписью, не только звёздочка.

**Ошибка поля:** граница 2 px `text-primary`, ниже иконка предупреждения и текст весом 500. Текст объясняет, что исправить: «Укажите телефон или email». Ошибка уровня формы — блок `surface-block` в начале формы, фокус переводится на него.

### Таблица

Белый фон, без внешней рамки; шапка `caption` серым; разделители `line-subtle`; строка при наведении `surface-block`, скругление по краям; первая колонка — ссылка `body-strong`; суммы выравниваются вправо; действия появляются при наведении и всегда видны при фокусе и на сенсорных экранах.

### Три уровня блоков

| Уровень | Вид | Где |
|---|---|---|
| **Подложка KPI** | Одна серая подложка `radius-xl`, отступ 8 px, внутри белые плитки `radius-lg` с зазором 8 px; плитка: отступы 20 × 16 px, подпись `small` серым, значение `display` с табличными цифрами | Ключевые показатели дашборда |
| **Серый блок** (`block.tsx`) | `surface-block`, `radius-xl`, отступ 8 px; шапка: `title-2` слева, ссылка со стрелкой справа; содержимое — белое поле `radius-lg` | Диаграммы, пустые и служебные разделы |
| **Лёгкая секция** (`section.tsx`) | Без подложки: `title-2`, ссылка справа, линия `line-subtle` под заголовком, содержимое с отступом 16 px | Сводки, списки «Новые лиды», «Просроченные задачи», будущие таблицы |

- Значение KPI не обрезается: длинная сумма уменьшается через `clamp()` до 24 px. С шага 13 вся плитка — ссылка на соответствующий список.
- Не ставить серый блок внутрь серого блока и не размещать подряд больше двух серых блоков одного размера — для перечней использовать лёгкие секции.

- **Колонка:** 272 px (не шире 80 % экрана), зазор 16 px. Шапка **над** полем, без подложки: название `title-3`, справа количество в серой капсуле; ниже сумма `small` серым. - **Закрытые стадии** отделены вертикальной линией `line-subtle` и иконками (кубок, крест) в шапке, чтобы результат не читался как следующий этап работы.
- **Горизонтальная прокрутка** только внутри области воронки, с привязкой к началу колонки и `scroll-padding`, чтобы первая колонка была выровнена по заголовку страницы.
- **Карточка:** `surface-card`, `radius-md`, отступ 14 px; название `body-strong`, компания и контакт `small`, сумма `body-strong` с табличными цифрами; меню «Сменить стадию» справа сверху; бейдж «Просрочено», если у сделки есть просроченная задача.
- **Без суммы:** текст «Сумма не указана», не «0 ₽».
- **Перетаскивание:** карточка приподнимается с тенью и наклоном не более 1°; колонка-цель получает фон `surface-control` и контур 2 px чёрный.
- **Отказ правила:** карточка возвращается на место, тост объясняет причину и даёт ссылку «Изменить сделку». Перенос в «Проиграна» открывает диалог причины. Изменение применяется после ответа сервера, а пока карточка помечена загрузкой.
- **Доступность:** перетаскивание дублируется меню «Сменить стадию» и клавиатурным режимом. Изменение объявляется через `aria-live`.

### Карточка сущности

Две колонки на широком экране (≥ 1280):

- Слева: заголовок, бейдж, быстрые действия, поля, лента активностей.
- Справа, в серых блоках: связанные записи (компания, контакт, сделки).

На узком экране связанные записи идут после полей. Пустая связь показана серым текстом без ссылки: у контакта «Компания не указана» и действие «Указать компанию»; у конвертированного лида «Компания удалена», «Контакт удалён», «Сделка не создана или удалена».

Компания и контакт сделки — независимые связи, поэтому в карточке сделки рядом с контактом показывается его собственная компания, если она есть. Совпадение компаний не проверяется и предупреждением не выделяется.

### Диалог конвертации

Заголовок «Конвертировать лид», поля заполнены данными лида.

1. **Контакт:** имя, email, телефон.
2. **Компания (обязательно):** сегментированный переключатель из двух пилюль; выбранная с чёрной заливкой.
   - «Новая компания» (по умолчанию): поле названия. При совпадении с существующей ниже подсказка «Такая компания уже есть» и действие «Выбрать её».
   - «Существующая»: выпадающий список с поиском.
3. **Сделка:** чекбокс «Создать сделку», раскрывает название, стадию и сумму.

Основная кнопка «Конвертировать» на время запроса заблокирована и показывает загрузку. После успеха диалог заменяется итогом со ссылками на контакт, компанию и, если создана, сделку.

### Лента активностей

Форма вверху с переключателем «Заметка / Задача». Задача: текст, дата срока. Сортировка: невыполненные задачи по сроку, затем остальное по дате создания, новые сверху. Отметка задачи — чекбокс 20 px с подписью для скринридера.

### Диалог, тост, пустые состояния, загрузка

- **Диалог:** белый, `radius-lg`, ширина 480 px, затемнение `rgb(0 0 0 / 0.4)`; фокус удерживается внутри, Esc закрывает; на телефоне — лист снизу. Подтверждение удаления перечисляет последствия: «Вместе со сделкой будут удалены 3 активности».
- **Заблокированное удаление:** диалог объясняет причину и даёт ссылки: «Сначала удалите или перепривяжите 2 контакта и 1 сделку».
- **Тост:** тёмная пилюля снизу по центру, как плашка на скриншотах (`surface-inverse`, белый текст, действие-ссылка); `aria-live="polite"`, для ошибок `role="alert"`. Ошибки сами не исчезают, успех скрывается через 4 секунды.
- **Пустое состояние** (`empty-state.tsx`): белое поле внутри серого блока; серый круг 48 px с иконкой раздела, заголовок `title-3`, пояснение `body` серым, не больше одной кнопки. «Лидов пока нет» + «Создать лид». При активных фильтрах: «По этим фильтрам ничего нет» + «Сбросить фильтры». В лёгкой секции — одна строка серым текстом без иконки.
- **Загрузка:** скелетоны блоков `surface-control`, без вращающихся индикаторов на всю страницу.

### Правила диаграмм

Обе диаграммы — **горизонтальные столбцы с одним рядом** (`indexAxis: "y"`), а не круговые. Причина проверена валидатором: пять оттенков серого не различимы как категории (соседние пары ΔE 12,6 при минимуме 15, два оттенка ниже контраста 3:1). На столбцах подпись на оси сама называет категорию, и цвет ничего не должен кодировать.

| Параметр | Значение |
|---|---|
| Цвет столбца | `--chart-primary` (не синий: акцент данные не кодирует) |
| Стадии «Выиграна» / «Проиграна» | `--chart-secondary` / `--chart-tertiary`, закреплены за стадией; подпись на оси обязательна |
| Толщина столбца | 20–24 px, зазор между столбцами не менее 2 px |
| Скругление конца | 4 px, основание прямое |
| Ось значений | Целые числа (`precision: 0`), начало с 0 |
| Сетка | Вертикальные линии 1 px `--chart-grid`, горизонтальных нет |
| Подписи | Inter 13 px, `--text-secondary`; цвет текста не зависит от столбца |
| Значение | Прямо у конца столбца, небольшим локальным плагином, без новой зависимости |
| Легенда | Нет: ряд один, блок называется заголовком |
| Подсказка | Тёмная, радиус 10 px, русский текст; для стадий — количество и сумма |
| Анимация | 300 мс при загрузке, отключается при `prefers-reduced-motion` |
| Нулевые значения | Категория остаётся на оси. Если все нули — пустое состояние вместо диаграммы |

**Контракт данных:** клиентский компонент получает только подготовленные значения через props: `{ labels: string[]; values: number[] }` плюс необязательные суммы для подсказки. Запросов к серверу и расчётов в нём нет. Регистрируются только нужные модули Chart.js.

**Доступность:** `<canvas>` с `role="img"` и `aria-label` с итогом. Текстовой альтернативой служат сводки ниже: они содержат те же числа.

Перед сдачей диаграммы просматриваются глазами на всех трёх ширинах: длинные подписи вроде «Концепция и смета» и «Квалифицирован» не должны пересекаться с данными.

## 7. Русский язык интерфейса

| Термин задания | В интерфейсе |
|---|---|
| Lead / Account / Contact | Лид / Компания / Контакт |
| Opportunity / Stage / Activity | Сделка / Стадия / Активность |
| note / task / done | Заметка / Задача / Выполнена |
| convert lead | Конвертировать лид |
| won / lost | Выиграна / Проиграна |
| Recent Leads / Overdue Tasks / Stuck Deals | Новые лиды / Просроченные задачи / Зависшие сделки |
| site / email / phone / referral / manual | Сайт / Почта / Телефон / Рекомендация / Вручную |

**Форматы** через `Intl` с локалью `ru-RU`:

- сумма: `7 400 000 ₽`, копейки только если есть;
- дата: `7 ноября 2026`, в таблицах `07.11.2026`;
- относительное: «Сегодня», «Завтра», «Просрочено на 3 дня», с корректным склонением (`Intl.PluralRules`).

**Тон:** обращение на «вы», действие в кнопке — глаголом («Создать сделку», не «ОК»). Сообщение об ошибке говорит, что случилось и что делать: «Нельзя закрыть сделку как выигранную: укажите сумму и контакт». Английские технические тексты и коды ошибок пользователю не показываются.

## 8. Доступность

- Контраст текста не ниже 4.5:1, границ элементов не ниже 3:1. Токены подобраны под это, числа указаны в разделе 3.1.
- Все действия доступны с клавиатуры; фокус с клавиатуры виден всегда (синее кольцо), после клика мышью кольца нет.
- Иконка без подписи имеет `aria-label` на русском. Подписи полей связаны с полями.
- `lang="ru"` в корневом `<html>`.
- Семантические таблицы, заголовки по порядку, один `h1` на страницу.

## 9. Чего не делать

- Лендинг, hero, маркетинговые блоки, cookie-плашка.
- Логотип, тексты, логотипы приложений или контент со скриншотов.
- Второй акцентный цвет; синий для данных, статусов, фонов и украшений; градиенты, размытие, стеклянные эффекты.
- Круговые диаграммы и категории, различаемые только оттенком серого.
- Тени у блоков и карточек в покое, рамки вокруг серых блоков.
- Ряды одинаковых серых прямоугольников; серый блок внутри серого блока.
- Несколько чёрных кнопок в одной области; чёрная и синяя кнопка рядом.
- Маркетинговые размеры заголовков (больше 40 px) в рабочих экранах.
- Смешение русского и английского в интерфейсе.
