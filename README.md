# Studio CRM

Локальная CRM-lite для агентства выставочных стендов, пространств и бренд-зон. Финальный проект курса: лиды, компании, контакты, сделки, воронка, активности и дашборд по текущему состоянию базы.

## Легенда

Агентство проектирует и строит выставочные стенды, пространства и бренд-зоны. Входящие запросы приходят с сайта, по почте, по телефону, через рекомендации, а часть менеджеры заводят вручную.

Продажа редко закрывается сразу. Менеджер квалифицирует лид, связывает его с компанией и контактным лицом, оценивает бюджет, уточняет площадку, сроки и формат работ, а затем ведёт сделку по этапам до успешного закрытия или отказа.

CRM помогает менеджерам не терять входящие запросы, видеть воронку сделок, помнить контактных лиц клиентов, отслеживать просроченные задачи и понимать, какой объём потенциальной выручки находится в работе.

## Локальный запуск

### Требования

- Node.js 24 LTS. На другой основной версии `npm` выведет предупреждение.
- PostgreSQL 16, запущенный локально на порту 5432. Docker не нужен.
- `psql` и `createdb` из поставки PostgreSQL.

### 1. Node.js

```bash
nvm install    # один раз: установит версию из .nvmrc
nvm use        # в каждом новом терминале
node -v        # v24.x
```

### 2. Роль и базы PostgreSQL

Команды выполняются от имени суперпользователя PostgreSQL. В Homebrew это ваш системный пользователь, в Linux обычно `sudo -u postgres`. Если базы уже существуют, пропустите этот шаг: существующие базы не нужно удалять или пересоздавать.

```bash
psql -d postgres -c "CREATE ROLE studio_crm LOGIN CREATEDB PASSWORD 'studio_crm';"
createdb -O studio_crm -T template0 -E UTF8 --locale=en_US.UTF-8 studio_crm
createdb -O studio_crm -T template0 -E UTF8 --locale=en_US.UTF-8 studio_crm_agent   # только для автотестов
```

| База | Назначение |
|---|---|
| `studio_crm` | Рабочая база приложения (`DATABASE_URL`). Для запуска и ручной проверки достаточно её |
| `studio_crm_agent` | База автотестов (`TEST_DATABASE_URL`). Тесты стирают её данные |

`CREATEDB` нужен Prisma для временной shadow-базы при `prisma migrate dev`. Локаль `en_US.UTF-8` обеспечивает регистронезависимый поиск по кириллице. Если вы задали другой пароль, укажите его и в `.env`.

### 3. Окружение, зависимости, схема, данные

```bash
cp .env.example .env   # DATABASE_URL, TEST_DATABASE_URL, APP_TIME_ZONE
npm ci                 # postinstall выполнит prisma generate
npm run db:deploy      # применит миграции к studio_crm
npm run db:status      # «Database schema is up to date!»
npm run db:seed        # загрузит демонстрационные данные в пустую базу
```

`db:deploy` только применяет готовые миграции и ничего не удаляет. Первая миграция создаёт таблицы, CHECK-ограничения активностей и шесть стадий воронки, поэтому база после неё уже работоспособна.

Ожидаемые сообщения, которые можно не учитывать:

- `npm warn install-scripts ... not yet covered by allowScripts` для пакетов Prisma и esbuild — Prisma CLI и клиент работают без этих скриптов;
- предложение Prisma обновиться (`npm i @prisma/client@latest`) — версия 6.19.3 зафиксирована условиями задания, обновлять не нужно;
- предупреждение `prisma db seed`, что `package.json#prisma` устарел, — альтернатива `prisma.config.ts` запрещена условиями задания.

### 4. Запуск

```bash
npm run dev                      # http://localhost:3000 → /dashboard
npm run build && npm run start   # production-режим, тоже http://localhost:3000
```

### 5. Проверки и автотесты

Перед первым запуском тестов примените миграции к тестовой базе:

```bash
npx tsx scripts/with-test-db.ts prisma migrate deploy
```

Затем:

```bash
npm run lint
npm run typecheck   # next typegen && tsc --noEmit
npm test            # 172 теста на studio_crm_agent
```

`npm test` запускается через обёртку `scripts/with-test-db.ts`: она подставляет `TEST_DATABASE_URL` вместо `DATABASE_URL` и отказывается работать, если это не локальная база `studio_crm_agent`. Рабочую базу тесты не затрагивают.

Что покрыто: контрольные данные и защиты seed/reset; валидация и правила удаления всех сущностей; фильтры и поиск в базе; конвертация лида (оба режима компании, со сделкой и без, отказы без частичных изменений, откат транзакции, повторные и параллельные вызовы, перенос активностей); смена стадии (все переходы, блокировки won и lost, устаревшая стадия, параллельные изменения); заметки и задачи (срок без сдвига часового пояса, «сегодня» и «просрочено» по `APP_TIME_ZONE`, отметка выполнения); показатели дашборда и их изменение после создания, правки, конвертации и удаления записей.

## Демонстрационные данные

| Команда | Что делает | Когда использовать |
|---|---|---|
| `npm run db:seed` | `prisma db seed` — загружает контрольный набор **только в пустую базу** | Первый запуск после `db:deploy` |
| `npm run db:reset` | Удаляет все лиды, компании, контакты, сделки и активности и загружает контрольный набор заново в одной транзакции | Вернуть демонстрационное состояние |

- `db:seed` на базе с данными ничего не меняет и завершается ошибкой с подсказкой про `db:reset`.
- `db:reset` не удаляет ни базу, ни схему, ни стадии воронки. Для любой базы, кроме `studio_crm_agent`, команда просит подтверждение: введите «да». Без интерактивного терминала сброс не выполняется, флага для пропуска подтверждения нет.
- Обе команды работают только с локальной базой (`localhost`, `127.0.0.1`, `::1`).

**Контрольный набор:** 6 лидов, 4 компании, 5 контактов (один без компании), 6 сделок, 8 активностей. Все компании и люди вымышленные. Сроки задач считаются от дня загрузки в часовом поясе `APP_TIME_ZONE`: две задачи просрочены, две назначены на сегодня. На следующий день задачи «на сегодня» станут просроченными, поэтому перед демонстрацией выполните `npm run db:reset`.

## Проверочный сценарий

Выполняется после `npm run db:reset` и `npm run dev`. В скобках — ожидаемый результат.

1. **Запуск.** Откройте http://localhost:3000 (открывается дашборд: 6 / 4 / 7 400 000 ₽ / 2).
2. **Лид.** «Лиды» → «Создать лид». Без имени контакта и без телефона или email лид не сохраняется (сервер повторяет проверку и при обходе формы). Заполните: Ольга Морозова, компания «Тестовая галерея», источник «Вручную», телефон. Сохраните (открывается карточка лида со статусом «Новый»).
3. **Редактирование.** «Изменить» → статус «В работе», бюджет 500 000 (карточка показывает изменения; статус «Конвертирован» в форме выбрать нельзя).
4. **Поиск и фильтры.** Поле поиска вверху: «ольга», «норд», «анна», «шоурум» (находятся лид, компания, контакт, сделка). В «Лидах» — фильтры по статусу и источнику, в «Сделках» — по стадии и по статусу; состояние фильтров хранится в адресе.
5. **Конвертация.** В карточке лида «Конвертировать». Режим «Новая компания» (название подставлено из лида), отметьте «Создать сделку»: «Экспозиция галереи», стадия «Бриф», сумма 500 000. Без имени контакта или названия сделки сервер не выполняет конвертацию. После успеха — статус «Конвертирован» и ссылки на компанию, контакт и сделку; повторно открыть `/leads/<id>/convert` нельзя («Лид уже конвертирован»).
6. **Связи.** Компания показывает контакт и сделку; контакт — компанию и сделку; сделка — компанию, контакт, стадию «Бриф» и лид, из которого создана. Дашборд: 7 / 5 / 7 900 000 ₽ / 2.
7. **Воронка.** «Воронка»: перетащите карточку «Экспозиция галереи» в другую открытую колонку (или кнопка ⇄ на карточке). Карточка сделки показывает ту же стадию.
8. **Правила won/lost.** На «Бренд-зона на форуме» выберите «Выиграна» (отказ: нужны сумма и контакт); «Проиграна» без причины (отказ). Сделка остаётся в «Бриф». «Экспозицию галереи» можно закрыть как выигранную: сумма и контакт есть.
9. **Активности.** В карточке сделки «Добавить заметку» и «Добавить задачу» со сроком на сегодня (метка «Сегодня»), отметьте задачу выполненной. Задача со сроком в прошлом получает метку «Просрочено» и появляется в «Просроченных задачах» дашборда.
10. **Быстрые действия.** В карточке компании в блоке «Сделки» → «Добавить» (компания подставлена в новую сделку). Остальные быстрые действия — шаги 5, 7, 9.
11. **Удаление.** Компанию со связанными контактами или сделками удалить нельзя, контакт, привязанный к сделке, — тоже: диалог объясняет причину. Удаление лида не затрагивает созданные из него записи.
12. **Дашборд.** Откройте дашборд после каждого изменения: KPI, диаграммы «Сделки по стадиям» и «Статусы лидов», сводки и списки соответствуют текущей базе, в том числе после перезагрузки и кнопки «Назад».

## Возможности

- Списки, карточки, создание, изменение и удаление лидов, компаний, контактов и сделок. Формы проверяются на сервере (Zod), ошибки показываются у полей и в начале формы.
- Карточки со связями: у компании — контакты и сделки, у контакта — компания и сделки, у сделки — компания, контакт, стадия, активности и исходный лид.
- Глобальный поиск по именам, названиям, email и телефону без учёта регистра; фильтры лидов по статусу и источнику, сделок — по стадии и статусу.
- Конвертация лида в одной транзакции: контакт, компания (новая или существующая), по желанию сделка; повторная и параллельная конвертация отклоняется на сервере.
- Kanban-воронка с перетаскиванием и кнопкой «Сменить стадию»; правила won и lost.
- Заметки и задачи со сроком, отметкой выполнения и метками «Сегодня» / «Просрочено».
- Отдельный дашборд, показатели считаются на сервере через Prisma `aggregate` и `groupBy`.

### Источники и статусы лида

| Источник (`source`, обязательно) | Подпись |
|---|---|
| `site` | Сайт |
| `email` | Почта |
| `phone` | Телефон |
| `referral` | Рекомендация |
| `manual` | Вручную |

| Статус (`status`) | Подпись | Примечание |
|---|---|---|
| `new` | Новый | По умолчанию при создании |
| `in_progress` | В работе | |
| `qualified` | Квалифицирован | |
| `disqualified` | Отклонён | Конвертация недоступна, пока лид не вернут в работу |
| `converted` | Конвертирован | Ставится только конвертацией, конечный |

Конвертированный лид изменить нельзя, но можно удалить: созданные из него компания, контакт и сделка остаются.

### Стадии сделки

| Стадия | Тип (`Stage.type`) | Статус сделки |
|---|---|---|
| Бриф | `open` | Открыта |
| Концепция и смета | `open` | Открыта |
| Согласование | `open` | Открыта |
| Договор | `open` | Открыта |
| Выиграна | `won` | Выиграна |
| Проиграна | `lost` | Проиграна |

- Статус сделки вычисляется из типа стадии, отдельного поля нет.
- Новая сделка создаётся только в открытой стадии; стадия меняется действием «Сменить стадию» (карточка сделки, доска).
- Перевод в «Выиграна» требует суммы больше нуля и контакта (их можно заполнить в диалоге), в «Проиграна» — причины. У выигранной сделки нельзя очистить сумму или контакт, у проигранной — причину. Возврат закрытой сделки в работу требует подтверждения.
- Если стадию успели сменить в другой вкладке, запрос отклоняется, и доска показывает актуальное состояние.

### Связи и удаление

- Контакт может существовать без компании. Сделка всегда связана с компанией; её контакт выбирается независимо и может относиться к другой компании.
- Компанию со связанными контактами или сделками удалить нельзя; контакт, привязанный к сделке, — тоже. Удаление записи удаляет её активности.

### Быстрые действия

| Действие | Где |
|---|---|
| Добавить заметку, добавить задачу | Лента «Активности» в карточке лида, компании, контакта и сделки |
| Создать сделку | «Добавить →» в блоке «Сделки» карточки компании или контакта (подставляются компания и контакт) |
| Сменить стадию | Карточка сделки и доска «Воронка» |
| Конвертировать лид | Карточка лида |

Задача — текст и срок (дата без времени). «Сегодня» определяется по `APP_TIME_ZONE` (по умолчанию `Europe/Moscow`), а не по времени браузера. Просроченная задача — невыполненная со сроком раньше сегодняшней даты.

### Дашборд

- KPI: всего лидов, открытых сделок, сумма открытых сделок, просроченных задач.
- Диаграммы Chart.js: сделки по стадиям воронки, статусы лидов.
- Сводки по статусам и источникам лидов.
- Списки: пять новых лидов; просроченные задачи — до 10 самых старых со ссылкой на запись (KPI считает все).

Данные агрегируются на сервере при каждом запросе; после изменений в CRM дашборд показывает актуальные значения при повторном открытии. WebSockets, подписки и push-уведомления не используются.

## Схема базы данных и миграции

Схема — [prisma/schema.prisma](prisma/schema.prisma), миграции — [prisma/migrations/](prisma/migrations/). Шесть моделей: `Lead`, `Account`, `Contact`, `Opportunity`, `Stage`, `Activity`. Правила связей и удаления — [Plan.md](Plan.md), раздел 1.8.

| Команда | Что делает |
|---|---|
| `npm run db:deploy` | `prisma migrate deploy` — применяет новые миграции, ничего не удаляет |
| `npm run db:status` | `prisma migrate status` — показывает, все ли миграции применены |
| `npm run db:migrate -- --name <имя>` | `prisma migrate dev` на тестовой базе `studio_crm_agent` — создаёт миграцию из изменений схемы (только для разработки) |

### Как безопасно изменить схему

1. Измените `prisma/schema.prisma`.
2. Создайте миграцию:
   ```bash
   npm run db:migrate -- --name <что_изменилось>
   ```
   Команда всегда работает с тестовой базой `studio_crm_agent` из `TEST_DATABASE_URL` и откажется запускаться, если переменная указывает на другую или нелокальную базу.
   Если нужен SQL, которого Prisma не описывает (CHECK-ограничения, данные справочников), добавьте `--create-only`, допишите SQL в созданный файл и запустите команду ещё раз без этого флага.
3. Проверьте файл миграции и примените его к рабочей базе: `npm run db:deploy`. Данные при этом сохраняются.

**Чего не делать:**

- не использовать `prisma migrate reset` и `prisma db push`: первая удаляет схему вместе с данными, вторая обходит миграции;
- если `migrate dev` предлагает сбросить базу, ответить «нет» и разобраться в причине расхождения;
- не редактировать уже применённые миграции — только создавать новые;
- не указывать базы проекта в `--shadow-database-url`: Prisma очищает shadow-базу перед использованием.

## Известные ограничения

- Нет авторизации, ролей и ответственных; одна валюта — рубли. Стадии воронки — справочник из миграции, в интерфейсе не настраиваются.
- Заметки и задачи нельзя изменить или удалить по отдельности — они удаляются вместе со своей записью.
- У конвертированного лида новые заметки и задачи не добавляются: его активности перенесены в созданную сделку или контакт, карточка лида даёт ссылку туда.
- При конвертации нет поиска дублей компании: существующую компанию нужно выбрать вручную в режиме «Существующая».
- «Зависшие сделки» (необязательный список дашборда) не реализованы. Список «Просроченные задачи» показывает до 10 задач, KPI считает все.
- Демонстрационные сроки задач привязаны ко дню загрузки данных: на следующий день выполните `npm run db:reset`.
- Интерфейс проверялся в Google Chrome (в том числе на ширине 1440, 1024 и 390 px); Safari, Firefox и реальные сенсорные устройства не проверялись.
