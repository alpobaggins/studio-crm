# Studio CRM

Локальная CRM-lite для агентства выставочных стендов, пространств и бренд-зон. Финальный проект курса и работа для портфолио.

> **Статус: планирование.** Код приложения ещё не написан, команд запуска пока нет. Инструкции появятся на шагах 02–04 и будут окончательно оформлены на шаге 14 ([Plan.md](Plan.md)).

## Легенда

Агентство проектирует и строит выставочные стенды, пространства и бренд-зоны. Входящие запросы приходят с сайта, по почте, по телефону, через рекомендации, а часть менеджеры заводят вручную.

Продажа редко закрывается сразу. Менеджер квалифицирует лид, связывает его с компанией и контактным лицом, оценивает бюджет, уточняет площадку, сроки и формат работ, а затем ведёт сделку по этапам до успешного закрытия или отказа.

## Назначение

CRM помогает менеджерам:

- не терять входящие запросы;
- видеть воронку сделок;
- помнить контактных лиц со стороны клиентов;
- отслеживать просроченные задачи;
- понимать, какой объём потенциальной выручки находится в работе.

## Границы MVP

**Входит:**

- сущности `Lead`, `Account`, `Contact`, `Opportunity`, `Stage`, `Activity`;
- создание, просмотр, изменение и удаление лидов, компаний, контактов и сделок;
- списки и карточки со связями между записями;
- поиск и фильтры по актуальным данным базы;
- упрощённая атомарная конвертация лида: создаётся контакт, компания обязательна — новая (по умолчанию) или существующая, при необходимости создаётся сделка; повторно конвертировать лид нельзя;
- Kanban-воронка с правилами перехода сделки в won и lost;
- активности: заметки и задачи со сроком и отметкой о выполнении;
- быстрые действия;
- отдельный дашборд;
- воспроизводимый локальный запуск: `.env.example`, миграции Prisma, seed/reset.

**Не входит:** авторизация, роли и назначение ответственных, несколько валют, импорт и экспорт, интеграции с почтой и телефонией, настройка стадий через интерфейс, real-time (WebSockets, Live Subscriptions, push), развёртывание на сервере, лендинг.

## Основной сценарий

Запуск → подготовка демонстрационных данных → создание лида → конвертация → проверка связанных карточек → движение сделки по воронке → заметка и задача → поиск и фильтры → дашборд → изменение лида или сделки и проверка обновления дашборда при повторном запросе.

## Статусы, стадии и источники

**Источник лида (обязательное поле):**

| Значение | Подпись |
|---|---|
| `site` | Сайт |
| `email` | Почта |
| `phone` | Телефон |
| `referral` | Рекомендация |
| `manual` | Вручную |

**Статусы лида:**

| Значение | Подпись | Примечание |
|---|---|---|
| `new` | Новый | Статус при создании |
| `in_progress` | В работе | |
| `qualified` | Квалифицирован | |
| `disqualified` | Отклонён | Конвертация недоступна |
| `converted` | Конвертирован | Ставится только конвертацией, конечный |

**Стадии сделки:**

| Стадия | Статус сделки |
|---|---|
| Бриф | Открыта |
| Концепция и смета | Открыта |
| Согласование | Открыта |
| Договор | Открыта |
| Выиграна | won |
| Проиграна | lost |

Статус сделки вычисляется из типа стадии (`Stage.type`: `open`, `won`, `lost`), отдельного поля нет. Фильтры по стадии и по статусу работают независимо. Перевод в won требует суммы и контакта, перевод в lost — причины отказа.

Контакт может существовать без компании. Сделка всегда связана с компанией, а её контакт выбирается независимо и может относиться к другой компании или не иметь её. Компанию со связанными контактами или сделками удалить нельзя.

## Быстрые действия

Создать сделку · сменить стадию · добавить заметку · добавить задачу · конвертировать лид.

## Показатели дашборда

- Карточки: всего лидов, открытых сделок, сумма открытых сделок, просроченных задач.
- Диаграммы Chart.js: сделки по стадиям воронки, распределение статусов лидов.
- Сводки: статусы лидов, источники лидов.
- Списки: новые лиды, просроченные задачи, опционально зависшие сделки.

Показатели считаются на сервере по текущему состоянию базы. После изменения записей дашборд показывает актуальные данные при повторном запросе.

## Планируемый стек

| Слой | Технология |
|---|---|
| Среда выполнения | Node.js 24 LTS (`.nvmrc`) |
| Приложение | Next.js (App Router), React, TypeScript |
| База данных | Локальный PostgreSQL 16, без Docker |
| ORM | `prisma@6.19.3`, `@prisma/client@6.19.3`; `DATABASE_URL` через `env("DATABASE_URL")` |
| Валидация | Zod |
| Диаграммы | `chart.js@4.5.1`, `react-chartjs-2@5.3.1` |
| Интерфейс | Tailwind CSS, `@dnd-kit/core`, `lucide-react` |
| Автотесты | `node:test` + `tsx` |

Точные версии остальных пакетов фиксируются на шаге 02. `@prisma/adapter-pg`, `PrismaPg` и `prisma.config.ts` не используются.

## Локальные базы данных

| База | Назначение |
|---|---|
| `studio_crm` | Рабочая база приложения. Этого достаточно для запуска и проверки |
| `studio_crm_agent` | Для автоматических проверок с изменением данных, включая dev и production. Для запуска приложения не нужна |

`db:seed` заполняет только пустую базу. `db:reset` восстанавливает демонстрационные данные: очищает строки таблиц и загружает их заново, не удаляя базу и схему. Вне `studio_crm_agent` команда требует подтверждения пользователя в терминале, флага для его обхода нет. Команды появятся на шагах 02–04.
