# Studio CRM

Локальная CRM-lite для агентства выставочных стендов, пространств и бренд-зон. Финальный проект курса и работа для портфолио.

> **Статус: конвертация лида (шаг 10).** Работают разделы «Лиды», «Компании», «Контакты» и «Сделки»: списки, карточки, создание, изменение и удаление. Карточки показывают связанные записи со ссылками: у компании — контакты и сделки, у контакта — компанию и сделки, у сделки — компанию, контакт и лид, из которого она создана. Поле поиска вверху каждой страницы ищет лиды, компании, контакты и сделки по имени, названию, компании, email и телефону без учёта регистра и показывает результаты на странице `/search` по группам. У лидов есть поиск и фильтры по статусу и источнику, у сделок — поиск и независимые фильтры по статусу и стадии; состояние фильтров хранится в адресе страницы. Стадия сделки выбирается при создании (только открытая), а меняется действием «Сменить стадию», которое появится вместе с воронкой на шаге 11. Лид конвертируется с экрана «Конвертировать лид» (кнопка в карточке лида): создаётся контакт, компания новая или выбранная из базы, по желанию — сделка в открытой стадии; всё выполняется одной транзакцией, повторная конвертация невозможна, активности лида переходят к сделке или контакту. Отклонённый лид нельзя конвертировать, пока его не вернут в работу. Дашборд и воронка пока показывают каркас без данных — они появятся на шагах 11–13. Инструкции окончательно оформляются на шаге 14 ([Plan.md](Plan.md)).

## Легенда

Агентство проектирует и строит выставочные стенды, пространства и бренд-зоны. Входящие запросы приходят с сайта, по почте, по телефону, через рекомендации, а часть менеджеры заводят вручную.

Продажа редко закрывается сразу. Менеджер квалифицирует лид, связывает его с компанией и контактным лицом, оценивает бюджет, уточняет площадку, сроки и формат работ, а затем ведёт сделку по этапам до успешного закрытия или отказа.

## Назначение

CRM помогает менеджерам:

- не терять входящие запросы;
- видеть воронку сделок;
- помнить контактных лиц со стороны клиентов;
- отслеживать просроченные задачи;
- понимать, какой объём потенциальной выручки находится в работе.

## Границы MVP

**Входит:**

- сущности `Lead`, `Account`, `Contact`, `Opportunity`, `Stage`, `Activity`;
- создание, просмотр, изменение и удаление лидов, компаний, контактов и сделок;
- списки и карточки со связями между записями;
- поиск и фильтры по актуальным данным базы;
- упрощённая атомарная конвертация лида: создаётся контакт, компания обязательна — новая (по умолчанию) или существующая, при необходимости создаётся сделка; повторно конвертировать лид нельзя;
- Kanban-воронка с правилами перехода сделки в won и lost;
- активности: заметки и задачи со сроком и отметкой о выполнении;
- быстрые действия;
- отдельный дашборд;
- воспроизводимый локальный запуск: `.env.example`, миграции Prisma, seed/reset.

**Не входит:** авторизация, роли и назначение ответственных, несколько валют, импорт и экспорт, интеграции с почтой и телефонией, настройка стадий через интерфейс, real-time (WebSockets, Live Subscriptions, push), развёртывание на сервере, лендинг.

## Основной сценарий

Запуск → подготовка демонстрационных данных → создание лида → конвертация → проверка связанных карточек → движение сделки по воронке → заметка и задача → поиск и фильтры → дашборд → изменение лида или сделки и проверка обновления дашборда при повторном запросе.

## Статусы, стадии и источники

**Источник лида (обязательное поле):**

| Значение | Подпись |
|---|---|
| `site` | Сайт |
| `email` | Почта |
| `phone` | Телефон |
| `referral` | Рекомендация |
| `manual` | Вручную |

**Статусы лида:**

| Значение | Подпись | Примечание |
|---|---|---|
| `new` | Новый | По умолчанию при создании |
| `in_progress` | В работе | |
| `qualified` | Квалифицирован | |
| `disqualified` | Отклонён | Конвертация недоступна |
| `converted` | Конвертирован | Ставится только конвертацией, конечный |

В форме лида можно выбрать любой статус, кроме «Конвертирован». Отклонённый лид можно вернуть в работу. Конвертированный лид изменить нельзя, но можно удалить: созданные из него компания, контакт и сделка при этом остаются.

**Стадии сделки:**

| Стадия | Статус сделки |
|---|---|
| Бриф | Открыта |
| Концепция и смета | Открыта |
| Согласование | Открыта |
| Договор | Открыта |
| Выиграна | won |
| Проиграна | lost |

Статус сделки вычисляется из типа стадии (`Stage.type`: `open`, `won`, `lost`), отдельного поля нет. Фильтры по стадии и по статусу работают независимо. Перевод в won требует суммы и контакта, перевод в lost — причины отказа.

Новая сделка создаётся только в открытой стадии, сумму и контакт можно указать позже. В форме изменения стадии нет. У выигранной сделки нельзя очистить сумму (она должна быть больше нуля) или контакт, у проигранной — причину проигрыша. Сервер проверяет эти правила при каждом сохранении, в том числе в обход формы. Суммы хранятся как `Decimal(14, 2)` и показываются с копейками, только если они есть. Удаление сделки удаляет её активности; компания, контакт и лид, из которого она создана, остаются.

Контакт может существовать без компании. Сделка всегда связана с компанией, а её контакт выбирается независимо и может относиться к другой компании или не иметь её. Компанию со связанными контактами или сделками удалить нельзя.

## Быстрые действия

Создать сделку · сменить стадию · добавить заметку · добавить задачу · конвертировать лид.

## Показатели дашборда

- Карточки: всего лидов, открытых сделок, сумма открытых сделок, просроченных задач.
- Диаграммы Chart.js: сделки по стадиям воронки, распределение статусов лидов.
- Сводки: статусы лидов, источники лидов.
- Списки: новые лиды, просроченные задачи, опционально зависшие сделки.

Показатели считаются на сервере по текущему состоянию базы. После изменения записей дашборд показывает актуальные данные при повторном запросе.

## Локальный запуск

### Требования

- Node.js 24 LTS. Версия указана в `.nvmrc` и в `engines` файла `package.json`; на другой основной версии `npm` выведет предупреждение.
- PostgreSQL 16, запущенный локально на порту 5432. Docker не нужен.

### 1. Node.js

```bash
nvm install    # один раз: установит версию из .nvmrc
nvm use        # в каждом новом терминале
node -v        # v24.x
```

### 2. Роль и базы PostgreSQL

Команды выполняются от имени суперпользователя PostgreSQL. В Homebrew это ваш системный пользователь; в Linux обычно `sudo -u postgres`. Если базы уже существуют, пропустите этот шаг: существующие базы не удаляются и не пересоздаются.

```bash
psql -d postgres -c "CREATE ROLE studio_crm LOGIN CREATEDB PASSWORD 'studio_crm';"
createdb -O studio_crm -T template0 -E UTF8 --locale=en_US.UTF-8 studio_crm
createdb -O studio_crm -T template0 -E UTF8 --locale=en_US.UTF-8 studio_crm_agent   # только для автотестов
```

`CREATEDB` нужен Prisma для временной shadow-базы при `prisma migrate dev`. Локаль `en_US.UTF-8` обеспечивает регистронезависимый поиск по кириллице. Пароль можно задать свой: тогда укажите его и в `.env`.

### 3. Окружение и зависимости

```bash
cp .env.example .env
npm ci              # postinstall выполнит prisma generate
npm run db:deploy   # применит миграции к базе из DATABASE_URL (studio_crm)
npm run db:status   # «Database schema is up to date!»
```

`db:deploy` только применяет готовые миграции и ничего не удаляет. Первая миграция создаёт таблицы, CHECK-ограничения активностей и шесть стадий воронки, поэтому база после неё уже работоспособна.

Затем загрузите демонстрационные данные в пустую базу:

```bash
npm run db:seed
```

Предупреждения npm 11 вида `install-scripts ... not yet covered by allowScripts` для пакетов Prisma и esbuild ожидаемы: Prisma CLI и клиент работают без этих скриптов.

### 4. Запуск

```bash
npm run dev                      # http://localhost:3000 → /dashboard
npm run build && npm run start   # production-режим
```

### Проверки

```bash
npm run lint
npm run typecheck   # next typegen && tsc --noEmit
npm test            # автотесты на studio_crm_agent
```

## Демонстрационные данные

| Команда | Что делает | Когда использовать |
|---|---|---|
| `npm run db:seed` | `prisma db seed` — загружает контрольный набор **только в пустую базу** | Первый запуск после `db:deploy` |
| `npm run db:reset` | Удаляет все лиды, компании, контакты, сделки и активности и загружает контрольный набор заново в одной транзакции | Вернуть демонстрационное состояние |

- `db:seed` на базе с данными ничего не меняет и завершается ошибкой с подсказкой про `db:reset`.
- `db:reset` не удаляет ни базу, ни схему, ни стадии воронки. Для любой базы, кроме `studio_crm_agent`, команда спрашивает подтверждение: введите «да». Без интерактивного терминала сброс не выполняется, флага для пропуска подтверждения нет.
- Обе команды работают только с локальной базой (`localhost`, `127.0.0.1`, `::1`).
- `prisma db seed` выводит предупреждение, что `package.json#prisma` устарел. Это ожидаемо: файл `prisma.config.ts` в проекте не используется по условиям задания.

**Контрольный набор:** 6 лидов, 4 компании, 5 контактов (один без компании), 6 сделок, 8 активностей. Все компании и люди вымышленные. Сроки задач считаются от сегодняшнего дня в часовом поясе `APP_TIME_ZONE`: две задачи просрочены, две назначены на сегодня. На следующий день задачи «на сегодня» станут просроченными, поэтому перед демонстрацией выполните `npm run db:reset`.

Сразу после seed или reset дашборд должен показать:

| Показатель | Значение |
|---|---|
| Всего лидов | 6 |
| Открытых сделок | 4 |
| Сумма открытых сделок | 7 400 000 ₽ |
| Просроченных задач | 2 |

Полная таблица контрольных значений — [Plan.md](Plan.md), шаг 04.

## Автотесты

`npm test` запускает тесты (`node:test` + `tsx`) только на базе `studio_crm_agent`: контрольные данные, защиты seed/reset, валидация и правила удаления компаний и контактов, лиды — валидация, статусы (`converted` нельзя назначить вручную и снять), фильтры и поиск в базе, удаление; сделки — создание только в открытой стадии, инварианты выигранной и проигранной сделки, контакт другой компании или без компании, точность сумм, фильтры по статусу и стадии, поиск, удаление; глобальный поиск и связанные записи карточек; конвертация лида — оба режима компании со сделкой и без, отказы без частичных изменений, откат транзакции при сбое, повторные и параллельные вызовы, перенос активностей. Обёртка `scripts/with-test-db.ts` подставляет `TEST_DATABASE_URL` вместо `DATABASE_URL` и отказывается работать, если это не локальная `studio_crm_agent`. Тесты сбрасывают данные этой базы, рабочую базу они не затрагивают.

## Схема базы данных и миграции

Схема описана в [prisma/schema.prisma](prisma/schema.prisma), миграции лежат в [prisma/migrations/](prisma/migrations/). Шесть моделей: `Lead`, `Account`, `Contact`, `Opportunity`, `Stage`, `Activity`. Правила связей и удаления — [Plan.md](Plan.md), раздел 1.8.

| Команда | Что делает |
|---|---|
| `npm run db:deploy` | `prisma migrate deploy` — применяет новые миграции, ничего не удаляет |
| `npm run db:status` | `prisma migrate status` — показывает, все ли миграции применены |
| `npm run db:migrate -- --name <имя>` | `prisma migrate dev` на тестовой базе `studio_crm_agent` — создаёт миграцию из изменений схемы (только для разработки) |

### Как безопасно изменить схему

1. Измените `prisma/schema.prisma`.
2. Создайте миграцию:
   ```bash
   npm run db:migrate -- --name <что_изменилось>
   ```
   Команда всегда работает с тестовой базой `studio_crm_agent` из `TEST_DATABASE_URL` и откажется запускаться, если переменная указывает на другую или нелокальную базу.
   Если нужен SQL, которого Prisma не описывает (CHECK-ограничения, данные справочников), добавьте `--create-only`, допишите SQL в созданный файл и запустите команду ещё раз без этого флага.
3. Проверьте файл миграции и примените его к рабочей базе: `npm run db:deploy`. Данные при этом сохраняются.

**Чего не делать:**

- не использовать `prisma migrate reset` и `prisma db push`: первая удаляет схему вместе с данными, вторая обходит миграции;
- если `migrate dev` предлагает сбросить базу, ответить «нет» и разобраться в причине расхождения;
- не редактировать уже применённые миграции — только создавать новые;
- не указывать базы проекта в `--shadow-database-url`: Prisma очищает shadow-базу перед использованием.
